# Final accessible-source absorption architecture

Trading Gym 11.0.0 adds a non-authoritative assurance layer above the existing institutional operating system. It does not create a second broker, accounting ledger, governance service, model registry, workflow executor, feature serving plane, or deployment authority.

## Evidence chain

```text
supplied donor ZIP
  -> safe extraction
  -> exact surface hash
  -> symbol and workflow extraction
  -> inherited adoption disposition
  -> static semantic-contract benchmark
  -> target symbol and acceptance test
  -> runtime/negative/recovery coverage
  -> mutation sensitivity
  -> accessible-source saturation report
```

## New bounded planes

1. **Behavioural benchmark registry** — distinguishes static contract evidence from differential runtime evidence.
2. **Feature-store parity** — checks ownership, freshness, point-in-time availability, and offline/online equality.
3. **Market replay** — validates sequence, chronology, payload hashes, chain continuity, and final-state identity.
4. **Financing inventory** — evaluates borrow availability, recalls, inventory ceilings, funding and projected costs.
5. **Performance attribution** — reconciles all components to authoritative accounting P&L.
6. **Knowledge impact** — performs bounded, temporal impact traversal without mutating the graph.
7. **Workflow assurance** — validates dependencies, idempotency, compensation, and human approval without running steps.
8. **Dynamic and mutation coverage** — measures runtime, negative, recovery and mutation evidence independently.
9. **Saturation gate** — requires exact surface, symbol, workflow, benchmark, plane, and authority closure.

## Authority boundaries

The new layer cannot:

- submit, cancel or route orders;
- borrow assets, move collateral or transfer funds;
- alter accounting or broker truth;
- serve online features;
- execute workflow steps;
- activate policies, models or deployments;
- certify legal, tax or regulatory compliance;
- infer unavailable Git history, issues, pull requests or donor runtime behaviour.

## Saturation meaning

“Saturation reached” means the exact supplied archive contents are fully accounted for under the configured evidence policy. It does not mean unavailable repository history or unavailable external execution environments were inspected.
