# ADR-034: Two-Horizon Agent Memory, Revisable Tools, and the Strategy Forge

**Status:** Accepted
**Date:** 2026-09-02

## Decision

The agent gains an explicit memory with two horizons, a tool registry that can be revised at runtime, and a strategy developer that produces candidates only through the existing gate chain. Four modules, one authority model — the agent may *propose* anything and *apply* nothing that ADR-033's gates have not passed:

1. **Short-term memory** (`trading_gym/agent/working_memory.py`). One `CycleRecord` per planner cycle — regime, fused-decision digest, invoked/benched arms, whether fusion escalated — bounded FIFO at `max_cycles`, strictly in-session, no filesystem. `settle` attaches the realized outcome afterwards. Memory is made *causal* by `CautionPolicy`: it reads the recent window (loss streak, escalation rate, realized P&L) and returns a `CautionState` that the planner applies to *this* cycle's fusion thresholds and leverage ceiling. Caution is **tighten-only by construction** — deltas are validated non-negative and the multiplier is validated ≤ 1 — so a poisoned or adversarial memory can shrink exposure and can force an escalation, but can never open a gate.
2. **Long-term memory** (`trading_gym/agent/persistent_experience.py`). An append-only, per-record-hashed journal at `TRADING_GYM_HOME/agent/memory/experiences.jsonl` with an anchor file, plus a *consolidated projection*: records with identical (tags, outcome, lesson) fold into one `Experience` whose `support` counts the observations and whose `last_seen_at` tracks the newest. Retrieval scores tag overlap (weight 10) with a recency-decay and bounded support tiebreak, so a lesson confirmed twenty times occupies one retrieval slot and outranks a fresher one-off without ever inverting overlap ordering. Retention prunes past `retention_days` at open, and the pruned state is the durable state. `advice()` returns a bounded digest — warnings from losses, confirmations from wins, each with support, plus a net signal in [-1, 1] — never raw rows.
3. **Revisable tools** (`trading_gym/agent/tools.py`). Every invocation is metered (calls, failures, last error, last call time). `revise` replaces a handler and bumps the tool's version; `retire` makes a tool refuse to run and removes it from `describe()` so it cannot be selected; both demand a reason and are journaled. `nominate` records a request for a tool the registry lacks — nomination grants no capability, and the durable, hash-chained queue is the ADR-033 revision ledger (`RevisionSurface.nominate` / `resolve_nomination` / `nominations`), because code is never self-revisable (ADR-033 §1, X-tier).
4. **Strategy forge** (`trading_gym/agent/forge.py` over `trading_gym/agent/strategy_variants.py`). Mutation happens *inside the declarative grammar*: integer indicator parameters and numeric comparison constants are jittered through `StrategySpec` construction, so an out-of-range period, an unknown parameter, or MACD `fast >= slow` raises instead of producing an invalid spec. Structure — which indicators exist, which operators compare them — is never mutated: that is an S-tier change needing replicated holdout evidence. Each candidate is scored exactly once by *real* playground runs over sealed holdout windows through the ADR-031→033 evidence bridge, the roster is ranked deterministically, and the winner is submitted to `RevisionSurface.submit`, which decides. The generation's outcome is written to long-term memory, and a memory dominated by losses narrows the next generation's mutation range (bounded, monotone, tighten-only).

Four new curated strategy families ship with it (`strategy_lab/templates.py`): ATR volatility breakout, OBV trend confirmation, Bollinger squeeze expansion, MACD histogram pullback — each validated, evaluable, and required by test to produce both entries and exits.

## Rationale

The planner was already deterministic over (context, regime, grants, budget) but had no way to know it had just lost four times in a row: without memory, the tenth losing cycle is indistinguishable from the first. Making the memory state an *explicit planner input* rather than hidden mutation keeps the L0/L1 replay property — the same inputs plus the same memory replay to the same decision — while letting the session's own history modulate risk. Tighten-only is the load-bearing constraint: memory is the one input an attacker or a bug could most easily poison, so its influence is structurally one-directional.

Long-term memory's problem is the opposite: unbounded growth and repetition. Twenty identical lessons should be one retrieval slot with twenty times the weight, not twenty slots crowding out everything else — hence consolidation with support, with the journal remaining the literal truth and the projection remaining readable. Hash-per-record makes lesson laundering (editing a `loss` into a `profitable`) fail the open rather than silently poisoning future decisions.

Tool revision exists because "the agent improves its tools" was previously indistinguishable from "the agent asserts a tool is broken". Metering supplies the evidence, the revision log supplies the reason and the actor, and retirement removes a tool from selection rather than leaving it callable-but-deprecated. Nomination is deliberately powerless: it is the only path from *the agent wants a funding-rate monitor* to a new tool, and it goes through humans.

The forge is the strategy-development counterpart to that discipline. Generating strategies as *code* would put an LLM's output on the execution path; generating them as grammar mutations makes the grammar the mutation bound, which is a checkable property rather than a review promise. Scoring with real playground runs over sealed windows means the forge cannot report a lift it did not earn — the seals are compared by the holdout-leakage gate.

## Consequences

- **Positive.** The self-improvement loop now has all three of its parts wired end to end: a candidate generator (forge), an evaluator (playground + bridge), and a gate (revision surface), with memory closing the feedback loop across generations and sessions. The planner degrades exposure automatically during a bad run without a new policy engine. Tool health is now evidence, not assertion.
- **Negative.** Caution is a blunt instrument: it tightens on realized P&L and escalation rate, both lagging signals, so it will occasionally shrink exposure during a drawdown that would have recovered. That is the intended asymmetry. The consolidated projection is rebuilt from the journal on every append, which is O(journal) per record — acceptable at the 500-entry default bound, and the reason retention prunes rather than accumulating.
- **Risks.** Memory poisoning (mitigated structurally: tighten-only caution, hash-verified journal, advisory-only advice); forge overfitting the sealed windows (mitigated by ADR-033's regression floor, diversity floor, and canary gates — the forge cannot self-approve); mutation-range narrowing collapsing the search (bounded: never below `lo + 1`).
- **Composition.** `WorkingMemory` outcomes are the caller's to feed into `PersistentExperienceMemory` at session close; the autonomy ladder (ADR-032) still decides which tiers may auto-apply; X-tier nominations feed the Donor Arsenal absorption pipeline (ADR-029). Tool revisions are in-process today — persisting them to the audit ledger is the next integration step.
