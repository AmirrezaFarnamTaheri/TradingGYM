# Accessible-source saturation runbook

## Preconditions

- Use the frozen target source and exact donor archives.
- Verify ZIP paths, collisions, CRC, member types, size and compression bounds before extraction.
- Do not import or execute donor code.
- Preserve the cumulative adoption ledger and surface matrix.

## Procedure

1. Scan every donor surface without following symlinks.
2. Reconcile each path and SHA-256 with the retained surface ledger.
3. Extract symbols, headings, markers and lifecycle candidates.
4. Link every extracted item to its containing surface disposition.
5. Verify all target-owned records resolve to current paths, symbols and unique tests.
6. Execute positive and negative contract tests.
7. Run mutation experiments against a disposable copy and prove the relevant tests fail.
8. Generate feature parity, replay, financing, attribution, knowledge and workflow reports.
9. Run the saturation gate.
10. Record unavailable history, issue/PR context and donor runtime environments as limitations.
11. Build the exact source and evidence archives once, verify their complete manifests, and promote the same bytes.

## Failure handling

- Any surface/hash mismatch blocks saturation.
- Any missing symbol or workflow mapping blocks saturation.
- Any failed or unverified configured benchmark blocks saturation.
- Any authority-bearing output blocks saturation.
- Any surviving mutation below the configured threshold blocks saturation.
- Missing optional history remains a limitation unless the policy explicitly requires it.

## Recovery

The process is analysis-only. Recovery consists of discarding generated reports and rerunning from the frozen source and donor archives. No live trading or accounting state is changed.
